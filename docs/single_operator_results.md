이 문서는 첫 단순화 완료 시점의 기록입니다. 이후 추가 지침으로 녹음을 21일 보관하고, 시작 기록을 평상시 기능으로 바꿨으며, 승인된 유료 사후 평가를 진행했습니다. 최신 결과와 교체 패키지는 [추가 지침 2 결과](/docs/addendum2_results.md)를 참고하세요. 아래 7일 보관과 진단 패키지 설명은 이전 상태입니다. 2026-11-09에는 다국어 사용을 막던 원문 언어별 숨김·음소거도 제거했습니다. 아래 6번과 2절은 당시 기록이며 현재 입력 언어 정책은 [STACK.md](/docs/STACK.md)의 5절이 기준입니다.

첨부 인계문의 1~8번과 10번을 구현하고, 9번은 승인용 목록과 화면 초안으로 작성했습니다. 추가 기능 삭제, 유료 API 호출, Git 커밋·푸시, 교회 설치 폴더에 대한 배포는 하지 않았습니다. 대부분 한국어인 프로젝트 문서는 한국어로 맞췄습니다. 한국어·영어 UI와 사용 안내의 기존 병기는 유지했습니다.

| 작업 | 반영 내용 |
|---|---|

| 2. 힌트·추천·입력 선택 제거 | `app/glossary.py`, `config/glossary.yaml`, 검토 모달과 전용 테스트를 삭제했습니다. 실제 존재하던 `/api/glossary/candidates`, `/api/glossary/entries`, `/api/glossary/add`도 제거했습니다. 언어·어휘 힌트, 추천·주석·검토 버튼·검토용 정지 후 별도 보관, 입력 선택·자동 감지·출력 충돌 검사를 제거했습니다. |

| 7. 채널 진단 | 캡처 시작과 매 60초에 채널별 RMS dBFS와 좌우 상관관계를 개발자 로그에 기록합니다. 화면 설정은 추가하지 않았습니다. |
| 8. 평가 도구 | 제공된 채점기와 자료를 `/tools/eval/`에 원본 그대로 복사하고 두 기준의 점수를 재현했습니다. 실행법과 비용 제안은 [전사 평가 문서](/docs/evaluation.md)에 있습니다. |
| 9. 남은 기능 감사 | 모든 남은 화면 조작·툴팁·설정·API·백그라운드 작업을 [승인용 감사 표](/docs/single_operator_audit.md)에 정리했습니다. 추가 삭제는 하지 않았습니다. |
| 10. 시작 지연 진단 | 배치 실행 전 시각부터 Python 시작·가져오기·설정·오디오·네트워크·mDNS·수신 시작·브라우저 호출까지 단계 로그를 추가했습니다. 서버 수신 후 브라우저를 열고 선택적 네트워크 점검은 별도 스레드에서 시작합니다. |

`app/model_resolver.py`는 수동 모델 연결 테스트 함수만 남겼습니다. 초기 설정 마법사의 수동 API 키·모델 검사는 실행 프로그램의 자동 카탈로그 검색과 달라 그대로 두었습니다. 두 항목의 추가 UI 정리는 9번 표에서 승인 대상으로 제안했습니다. 출력 언어 관리, QR·접속 링크, 네트워크 세부 진단, 인증과 이벤트 로그도 유지했습니다.

## 2. 언어 숨김과 복귀의 검증 범위

허용 원문 언어는 아래 한 줄로 설정합니다. 드문 초청 설교 때만 직접 수정하며 모델 힌트나 출력 선택에 사용하지 않습니다.

```yaml
translation:
  expected_source_languages: [ko, en]
```

원문 언어 코드가 오기 전의 자막은 잠시 보류합니다. 끝까지 코드가 확인되지 않은 전사는 표시·저장에서 제외하되, 이를 세 번의 외국어 확인 횟수로 세지는 않습니다. 예상 밖 언어가 감지되면 대기 자막을 지우고, 세 번째 연속 확인 이후에는 새 음성 청크를 송출하지 않습니다. 서버 큐와 브라우저의 예약 재생도 비우므로 별도의 오디오 버퍼나 지연을 추가하지 않았습니다.

언어 코드가 이미 허용 언어로 왔다가 뒤늦게 바뀌면 대기 표시와 해당 전사 저장은 막을 수 있지만 이미 전달·재생한 내용까지 되돌릴 수는 없습니다. 이 제한 때문에 실시간 전부 차단을 절대 보장한다고 표현하지 않습니다. 영어를 한글로 적으면서 `ko`라고 보고한 오류도 이 처리만으로 식별하지 못합니다.

11월 8일 로그에서는 **수동 조작 없는 복귀**를 확인했습니다. 11:13:51.988에는 베트남어가 기록되었고 11:13:56.145에는 `사도신경으로`라는 한국어가 돌아왔습니다. 11:13:59.075에는 이탈 확인 수가 0으로 초기화됐습니다. 직전 연결은 11:09:15.879의 epoch 1이며 이 구간에 Pause/Resume 기록이 없습니다.

## 3. 녹음과 빌드 검증

- 저장 위치는 `logs/recordings/current_week/`, 이름은 `2026-11-15_1045.mp3` 형식입니다. 같은 분에 다시 시작하면 숫자 접미사로 충돌을 피합니다.
- 번역 일시정지 중에도 캡처·녹음은 계속됩니다. 별도 WAV 백업은 만들지 않습니다. 큐가 가득 차거나 캡처가 끊긴 시간은 메타데이터와 무음으로 보존합니다. 누락된 실제 소리를 복원하는 것은 아닙니다.
- 새 녹음을 시작할 때 생성 형식에 맞는 파일 중 7일이 지난 것만 정리합니다. 주중 시험 때문에 지난 주일 녹음이 지워지지 않으며, 잠긴 옛 파일은 경고만 남깁니다.
- `lameenc 1.9.0`을 EXE에 포함하므로 녹음용 별도 FFmpeg 실행 파일은 필요하지 않습니다. FFmpeg는 개발 PC의 결과 디코딩 검증에만 사용했습니다.
- 실제 EXE의 검증 경로에 48 kHz 스테레오 시험 PCM을 넣어 정상 종료본과 프로세스 강제 종료본을 만들었습니다. 두 MP3 모두 128 kbps로 식별되고 디코딩되며, 양쪽 채널에 신호가 있었습니다. 실제 USB 수신기의 다음 예배 동작을 대신 검증한 것은 아닙니다.
- 전체 테스트는 **135개 통과**했습니다. 제거한 기능의 테스트를 정리하고 자막·음소거·이름 교정·녹음 검증을 추가했으므로 이전 195개와 단순히 개수를 비교하지 않습니다. 기존 SDK의 deprecation 경고 한 건이 남습니다.
- 전용 Playwright Chrome에서 삭제 UI의 부재, 고정 모델, 출력 선택, 교정된 커밋, 숨김·예약 음원 제거, 한영 표시, 네트워크 접기와 1024px 배치를 확인했습니다. 화면 시험은 API 변경 요청을 차단한 fixture로 실행했습니다.

공유 Conda 환경을 바꾸지 않으려고 테스트용 MP3 인코더는 프로젝트 안에 설치했습니다. 최종 전체 테스트 명령은 다음과 같습니다.

```powershell
$env:PYTHONPATH = (Resolve-Path '.agent/build_deps/agent').Path
conda run --no-capture-output -n agent python -m pytest tests/ --basetemp=.agent/scratch/single_operator/verified-source -q -p no:cacheprovider
```

정확한 빌드 크기·해시·녹음 길이·시작 측정은 [EXE 빌드 기록](/docs/BUILD_EXE.md)과 `.agent/archive/2026-11-08-worship-review/single_operator_build/verification_final.json`에 기록했습니다. 당시 파일은 [진단 패키지 보관본](../.agent/archive/2026-11-08-worship-review/single_operator_build/SKC_single_operator_diagnostic_20261108.zip)입니다. 시험용 `.env`와 중복 실행 폴더는 정리했으며 이 보관본을 현재 배포본으로 사용하지 않습니다.

## 6. 교회 노트북에서 할 일

저장소의 기존 `SKC_start.bat`는 Conda에서 `python main.py`를 실행했습니다. 약 5초라는 보고가 같은 EXE 빌드와 같은 환경에서 측정됐다는 근거는 없으므로 교회 노트북의 1~2분과 직접 비교하지 않습니다. 개발 PC에서 최종 소스의 HTTP 응답까지 단일 EXE는 7.226초, 단일 폴더는 19.417초였습니다. 캐시·백신·첫 실행 상태를 통제한 반복 측정이 아니므로 빌드 형식을 원인으로 확정하지 않았습니다.

진단 패키지를 적용할 때 기존 `.env`, `config.yaml`, `branding/`은 유지합니다. 패키지의 `config.example.yaml`은 참고용이며 기존 설정을 덮어쓰지 않습니다.

**평소처럼 `SKC_start.bat`를 실행한 뒤 `logs/startup.log` 파일을 보내 주세요.**

그 로그의 배치 시작과 Python 시작 사이가 길면 추출·실행 전 구간을, 가져오기·오디오·네트워크 등의 개별 단계가 길면 해당 구간을 조사합니다. 교회 로그를 받기 전에는 그 원인을 확인했다고 주장하거나 추가 성능 수정을 하지 않습니다.
