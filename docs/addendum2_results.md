# 추가 지침 2 반영 결과

어휘·언어 힌트 보관, 승인된 사후 전사 평가, 21일 녹음 보관, 할당량 오류 처리와 평상시 시작 기록을 반영했습니다. Git 커밋·태그·스태시·브랜치 변경과 교회 배포는 하지 않았습니다. 추가 유료 평가나 자동 백업 전사 기능도 만들지 않았습니다.

이후 인코더 접근 거부의 원인 안내를 보완했습니다. 제한된 에이전트 실행의 실패를 백신 차단으로 확정하지 않으며, 다음 평소 빌드에 반영할 진단 코드와 대응 절차는 [빌드 문서](/docs/BUILD_EXE.md)에 있습니다. 아래 패키지와 테스트 수는 당시 빌드의 기록입니다.

## 1. 제거 기능 보관

[어휘·언어 힌트 보관 문서](/docs/archive/어휘_언어힌트_보관.md)에 과거 세 계층, 설정·API·화면·관련 테스트, 제거 근거, 복원 순서와 채택 기준을 정리했습니다. [원본 용어 파일](/docs/archive/glossary_terms.yaml)은 마지막 커밋의 `/config/glossary.yaml`과 바이트가 같습니다.

- 복구할 커밋: `3000d9ddbb96049f176b5c251dfa3778d35a6f26`.
- 원본 용어집 SHA-256: `7d7df6c845837aa2feba3ec922894b4dcfc06311104519048f9e2f401817e5c0`.
- Google이 번역 모델용 어휘·원문 언어 설정을 공식 지원할 때만 재검토합니다. 사후 전사 모델의 지원을 번역 모델의 지원으로 해석하지 않습니다.
- 재채택에는 두 기준 모두 발화 CER가 2%p 넘게 개선되고 교회명·카미카 사실 검사를 통과해야 합니다. `/docs/PLAN.md`에도 보류 항목으로 연결했습니다.

기존 `v3.3.0`에 같은 핵심 구현이 있으므로 보관 태그 추가는 선택 사항입니다. 문서까지 포함한 기준 커밋에 별도 이름을 남기고 싶을 때만 다음 명령을 실행합니다. 이번 작업에서는 실행하지 않았습니다.

```powershell
git tag archive/vocab-hints-v3.3.0 3000d9ddbb96049f176b5c251dfa3778d35a6f26
```

## 2. 승인된 사후 전사 평가

유료 프로젝트의 `.env` 키임을 확인한 뒤 `gemini-3.5-transcribe`로 90분 15초 음원 전체를 한 번 평가했습니다. 원본을 45분 경계에서 두 개의 무손실 FLAC으로 나누고, 보관 용어·변형 표기와 다섯 고유명사 등 174개 어휘, 한국어·영어 언어 힌트, verbatim 설정을 사용했습니다. 두 요청을 한 번씩 실행했고 재시도하지 않았습니다. 업로드한 원격 파일은 삭제했습니다.

| 발화 구간 기준 | 기존 실시간 전사 CER | 사후 전사 CER | 차이 |
|---|---:|---:|---:|
| Gemini 전체 전사본 | 18.0393% | 22.5745% | 4.5352%p 악화 |
| ChatGPT 전체 전사본 | 19.0616% | 19.8544% | 0.7928%p 악화 |

Gemini 기준 설교만 보면 18.0241%에서 12.1472%로 개선됐습니다. 교회명·카미카와 도움 요청의 방향도 좋아졌지만, 신앙고백·기도 등 일부가 크게 빠졌습니다. 요청은 완료 상태였고 명시적 잘림 사유는 반환되지 않았습니다. 원본 MP3를 디코딩한 PCM과 두 FLAC을 합쳐 디코딩한 PCM의 바이트·해시가 일치하므로 분할 중 음원을 잃어버린 결과는 아닙니다. 영어 구절 유지 지표도 악화됐습니다.

두 기준은 모두 기계 전사본이며 채점기는 자유 정렬을 사용합니다. 따라서 이 결과를 사람이 검수한 정확도나 모든 누락을 검출하는 지표로 보지 않습니다. 구간별 점수·사실 검사·원시 응답·어휘와 비용 계산은 [평가 문서](/docs/evaluation.md)에 있습니다. **예배 전체 기준으로 명확히 좋아지지 않았으므로 `SKC_backup_transcript.bat` 도구를 구현하지 않았습니다.** 설교 구간의 개선은 유용한 출발점으로 보존하고, YouTube 오디오가 빠졌을 때 MP3 더빙·정렬과 필요한 구간의 요청형 전사를 검토하는 [보조 복구 계획](/docs/PLAN.md)으로 남깁니다. 실시간 통역을 대체하거나 매주 자동 실행하는 계획은 아닙니다.

이번 API가 보고한 입력 토큰은 135,378개, 출력 토큰은 9,805개입니다. 공개 단가로 계산한 사용 비용은 **US$0.388416**입니다. 청구서의 확정 금액에는 접근하지 못했으므로 실제 청구 확인액과 구분합니다. 입력 US$2/100만 토큰, 출력 US$12/100만 토큰으로 계산했습니다. [공식 단가](https://ai.google.dev/gemini-api/docs/pricing/).

## 3. 녹음 보관과 할당량 처리

- MP3 녹음은 고정 21일 보관입니다. 새 녹음 시작 시 21일을 넘긴 생성 파일만 정리하고, 정확히 21일인 파일과 잠긴 파일은 보존합니다. 설정이나 UI는 추가하지 않았습니다.
- 429, `RESOURCE_EXHAUSTED`, 청구·할당량 오류에서는 지출 한도·할당량·요청 빈도 제한의 가능성을 한국어·영어로 표시합니다. 오류 코드만으로 월 지출 한도를 확정하지 않습니다.
- 2초·5초 뒤 재시도하고 세 번째 실패에서 중단합니다. 잠시 연결에 성공해도 같은 제한 오류의 예산이 초기화되지 않습니다. 서버의 바깥 자동 재시작도 이 오류에서는 실행하지 않습니다.
- 실패한 언어의 큐를 더 채우지 않으며, 모든 언어가 실패하면 추정 과금 시간을 멈춥니다. 입력 녹음은 서비스 종료 전까지 계속합니다. 서비스 종료 후 결제·할당량을 확인하고 다시 시작하면 됩니다.
- 비용과 운영 결정은 [STACK의 비용 절](/docs/STACK.md)에 모았습니다. 평소 한 출력 언어, 인사부터 축도까지 운영하며 찬양 중 수동 전환과 자막 전용 재구현은 재제안하지 않습니다.

## 4. 별도 진단 실행 없는 시작 기록

`SKC_start.bat`을 평소처럼 실행하면 `logs/startup.log`에 날짜·단계별 소요 시간과 `startup_summary` 한 줄이 남습니다. 요약에는 전체 경과 시간과 가장 느린 단계가 있습니다. Python이 뜨기 전의 실행 지연도 최장 단계 후보에 넣습니다.

```text
Startup 2026-11-15 10:41:00: browser launch requested after 74.2s (slowest phase application_imports 51.8s)
```

위 숫자는 형식 예시입니다. 브라우저 실행 요청 시각이며 실제 화면 그리기 완료 시각은 아닙니다. 서버 수신 후 선택적으로 진행하는 네트워크 작업은 따로 표시합니다. 로그는 1 MiB마다 순환하고 백업 하나를 두므로 두 파일 합계 약 2 MiB로 제한됩니다. 설정과 UI는 없습니다. 다음 주일의 평상시 실행 후 필요할 때 이 파일을 보내면 되며 주중에 별도 진단을 실행할 필요가 없습니다.

## 5. 검증과 교체 패키지

- 전체 테스트: **150개 통과**, 기존 SDK deprecation 경고 1건, 17.43초. 첫 샌드박스 실행에서는 프로젝트 내부 MP3 네이티브 DLL의 로드가 차단됐습니다. 원인을 `Access is denied`로 확인한 뒤 같은 소스를 네이티브 DLL 로드가 허용된 실행에서 검증했습니다.
- 브라우저: 전용 Playwright Chrome에서 한영 할당량 안내, 재연결·최종 실패, 주·보조 언어 상태, 실패 시 재시도 비활성·서비스 종료 활성, 종료 후 안내 해제와 1024px 배치를 확인했습니다. 실제 API·마이크를 사용하지 않은 fixture 검증입니다.
- 설정: 보존된 11월 3일 배포본의 `config.yaml` 복사본을 수정 없이 읽었습니다. 이전 모델·원문 선택 키는 무시하고 기본 고정 모델과 `[ko, en]`을 사용하며 출력 언어는 유지합니다. 복사 전후 SHA-256은 `69a6afd5975b944c087116422219a873abc596e574b701ffc91ea62799686370`으로 같습니다. 이후 교회 PC에서 별도로 수정한 파일은 제공받지 않았으므로 그 파일까지 직접 검사했다고 주장하지 않습니다.
- 최종 EXE: 내장 코드·자산 42개가 현재 소스와 일치했습니다. 수정하지 않은 이전 설정으로 정상 녹음한 8.040초 MP3와 강제 종료한 3.638초 MP3가 모두 48 kHz 스테레오·128 kbps로 디코딩됐습니다. 안전한 새 폴더 실행에서는 운영자 페이지·로고 응답, 정상 종료, 시작 요약 1회와 로그 순환을 확인했습니다. 실제 교회 마이크와 공용 터널을 작동시킨 검증은 아닙니다.

당시 파일은 [검증 패키지 보관본](../.agent/archive/2026-11-08-worship-review/addendum2_release/SKC_live_translation_v3.4.0_20261108.zip)으로 옮겼습니다. EXE·MP3·설정 호환성과 당시 크기·해시는 [빌드 기록](/docs/BUILD_EXE.md)을 참고하세요. 이후 소스의 진단·화면 수정까지 포함하려면 평소처럼 현재 소스를 빌드합니다. 이 ZIP은 과거 검증 증거이며 현재 빌드를 대신하지 않습니다.

이 ZIP은 요청에 따라 준비한 전달용 산출물입니다. 직접 빌드해서 현재 버전을 교체하는 평소 작업 방식에서도 같은 기능을 사용하므로 ZIP이 필수는 아닙니다. 사용자가 보존한 이전 정상 버전은 그대로 유지합니다.

ZIP 크기는 94,382,581바이트, SHA-256은 `b93821a1c6dcf466153ae4ce5c786434f04cb79809a04defa98b02c33d640e8f`입니다. `.env*`, 실제 키, 활성 `config.yaml`은 포함하지 않았습니다. 필요한 기존 cloudflared와 고지, 한국어 설치·복구 안내는 포함했습니다.

1. 예배 전 여유 있게 현재 설치 폴더의 이름을 바꿔 이전 버전을 보존합니다.
2. 새 폴더에 ZIP을 풀고 이전 폴더의 `.env`, `config.yaml`, `branding/`을 복사합니다. 참고용 설정으로 기존 설정을 덮어쓰지 않습니다.
3. 새 폴더의 `SKC_start.bat`을 평소처럼 실행하고 예배를 진행합니다. MP3와 시작 기록은 자동 저장됩니다.
4. 문제가 있으면 새 프로그램을 완전히 종료한 뒤 이전 폴더의 `SKC_start.bat`을 실행합니다.
5. 편할 때 새 폴더의 `logs/startup.log`를 전달합니다. 있으면 `startup.log.1`도 함께 보냅니다.
