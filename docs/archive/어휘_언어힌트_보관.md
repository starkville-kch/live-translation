# 어휘·언어 힌트 기능 보관

2026-11-08에 Live Translate에서 효과를 확인하지 못한 기능을 제거했습니다. 이 문서는 Google이 해당 기능을 공식 지원할 때 복원할 위치와 재검증 기준을 남깁니다. 현재 실행 코드에서 사용하지 않습니다.

## 복구 기준점

- 제거 전 전체 기능을 포함한 보관 기준 커밋: `3000d9ddbb96049f176b5c251dfa3778d35a6f26`.
- `/config/glossary.yaml`은 위 커밋의 원본 바이트 그대로 [glossary_terms.yaml](/docs/archive/glossary_terms.yaml)에 보관했습니다. SHA-256은 `7d7df6c845837aa2feba3ec922894b4dcfc06311104519048f9e2f401817e5c0`입니다. 원문의 주석과 비활성 항목도 보존했습니다.
- 전체 사용처는 [제거 전 의존성 목록](/docs/simplification_dependencies.md)에 있습니다. 복원할 때는 `git show <커밋>:<경로>`로 이전 코드를 읽고 현재 코드에 필요한 부분만 다시 적용합니다.
- 기존 `v3.3.0` 태그(`aa469ddddc8b554069c1c11e23be2750f40ac2b0`)에도 같은 핵심 구현이 있습니다. 위 기준 커밋까지의 차이는 문서·안내·설정 화면 이미지이므로 새 보관 태그는 필수가 아닙니다.
- 문서까지 포함한 기준점에 별도 이름을 남기고 싶을 때만 다음 태그를 추가합니다. 태그는 브랜치나 작업 중 파일이 아니라 지정한 커밋을 가리킵니다. 이번 작업에서는 태그를 만들지 않았습니다.

```powershell
git tag archive/vocab-hints-v3.3.0 3000d9ddbb96049f176b5c251dfa3778d35a6f26
```

## 과거의 세 계층

| 계층 | 당시 동작과 관련 파일 |
|---|---|
| 연결 시 힌트 | `/app/gemini_session.py`에서 `AudioTranscriptionConfig`에 입력 언어 `language_codes`와 `custom_vocabulary`를 넣었습니다. 일반 모델용 프롬프트 경로도 있었으나 번역 전용 모델에서 효과가 입증되지 않았습니다. |
| 로컬 용어 교정 | `/app/glossary.py`의 `GlossaryCorrector`가 원문의 한국어 용어를 확인하고 확정된 영어 자막을 교정했습니다. `direct`는 활성 항목만 치환하고, `review_only`는 감지 로그만 남겼습니다. 음성 합성 결과는 바꾸지 않았습니다. |
| 주간 수집과 2분 검토 | 종료된 전사에서 기존 사전에 없는 후보를 빈도·예문과 함께 제안했습니다. 운영자가 검토 모달에서 추가하면 YAML과 메모리를 갱신했습니다. 자동으로 정답을 확정하는 기능은 아니었습니다. |

입력 언어 선택은 `ko`, `en`, `ko+en`과 `any` 자동 감지를 지원했습니다. 선택값은 힌트, 언어 이탈 허용 범위, 용어집 사용 여부, 입력·출력 충돌 검사와 전사 라벨에 연결되어 있었습니다. 첫 단순화의 `translation.expected_source_languages: [ko, en]`는 로컬 출력 보호용이었으며 이 과거 기능을 복원한 것이 아닙니다. 2026-11-09부터는 다국어 사용을 위해 이 설정도 무시합니다.

## 설정·API·화면

과거 설정의 핵심 형태는 다음과 같습니다. 이 예제를 현재 설정에 다시 넣어도 제거된 기능은 실행되지 않습니다.

```yaml
gemini:
  preferred_model: gemini-3.5-live-translate-preview
  fallback_model: gemini-3.5-live-translate-preview
  context_seed: true
translation:
  expected_source_language: ko+en  # any는 자동 감지
  supported_targets: [en, ko, uk, zh, es]
  default_active_targets: [en]
```

용어 파일은 `direct`의 `category`, `enabled`, `ko`, `en`, 선택적 `variants`와 `review_only`의 `ko`, `note`로 구성됐습니다. 범주는 직분·정치, 예배·성례, 신앙고백, 개혁주의 교리, 성경 인명, 한인 공동체 용어였습니다.

실제 REST 경로는 `GET /api/glossary/candidates`, `GET /api/glossary/entries`, `POST /api/glossary/add`였습니다. 운영자 화면에는 원문 언어 선택·자동 감지, 검토 버튼, 후보·등록 항목 모달과 설명 툴팁이 있었습니다. 관련 구현은 `/app/server.py`, `/app/broadcast.py`, `/app/translation_manager.py`, `/app/config.py`, `/app/languages.py`, `/app/static/js/operator.js`, `/app/static/css/operator.css`, `/app/templates/operator.html`, `/app/templates/operator/_language_targets.html`에 분산되어 있었습니다.

관련 검증은 `test_glossary_adaptation.py`, `test_translation_config.py`, `test_gemini_multilingual.py`, `test_anti_contamination.py`, `test_drift_recovery.py`, `test_translation_manager.py` 및 운영자·언어별 라우팅 테스트에 있었습니다. 전용 테스트는 제거했고, 유지되는 동작의 테스트는 현재 구조에 맞췄습니다.

## 제거 근거와 재검토 조건

2026-11-08 확인한 Google 문서에서 Live Translate의 번역 설정은 `target_language_code`와 `echo_target_language`입니다. `language_codes`와 `custom_vocabulary`는 전용 전사 모델인 `gemini-3.5-transcribe-live`와 `gemini-3.5-transcribe`의 기능으로 문서화되어 있습니다. 공통 SDK에 필드가 있다는 사실만으로 번역 모델의 지원을 가정하지 않습니다. [Live Translate](https://ai.google.dev/gemini-api/docs/live-api/live-translate), [실시간 전사](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe), [사후 전사](https://ai.google.dev/gemini-api/docs/transcribe).

11월 8일의 동일 음원 두 쌍 비교에서 힌트 유무에 따른 영어 구절 유지 차이는 없었습니다. 힌트를 켠 도입부에서도 교회 이름이 `스타필드 한인 교회`로 잘못 나왔습니다. 이 비교는 짧은 클립의 관측이며 모든 상황에서 효과가 없음을 증명하지는 않습니다. 원시 증거는 `.agent/archive/2026-11-08-worship-review/live_validation_20261108/`와 `.agent/sessions/20261108_121729/validation-walkthrough.md`에 보존했습니다. 전체 예배의 기존 실시간 원문은 새 두 기계 기준본 대비 발화 CER 18.0%·19.1%였습니다. 측정과 한계는 [전사 평가 문서](/docs/evaluation.md)에 있습니다.

Google이 **Live Translate 모델의 어휘 또는 원문 언어 설정을 공식 문서화하거나, 이를 지원하는 새 실시간 번역 모델을 출시할 때만** 재검토합니다. 별도 전사 모델에서의 개선만으로 번역 모델에 다시 넣지 않습니다.

2026-11-09에는 사용자 승인으로 찬양 중 언어 이탈을 따로 재생했습니다. 기준에서 재현됐고 `language_codes=["ko", "en"]`만 추가한 3회에서도 예방되지 않았습니다. 이 조건에서의 결과를 모든 언어 힌트의 무용성으로 일반화하지 않습니다. 원시 결과·비용·세션 재개 조사와 현재 유지 권고는 [찬양 중 언어 출력 조사](/docs/song_language_investigation.md)에 있습니다.

재활성화 전에는 다음을 모두 확인합니다.

1. 같은 11월 8일 클립과 같은 PCM을 새 설정 사용·미사용으로 비교합니다. 모델·SDK·설정·음원 해시·비용을 함께 기록합니다. 유료 호출은 먼저 승인을 받습니다.
2. `/tools/eval/score_transcript.py`로 두 전체 기준본과 `/tools/eval/data/2026-11-08/facts.json`에 모두 채점합니다. 짧은 클립만으로 전체 발화 CER를 주장하지 않고, 발화 구간을 충분히 포함한 동일 범위 평가를 합니다.
3. 교회 이름과 카미카 관련 사실 검사가 통과하고, 발화 CER가 **양쪽 기준에서 모두 2%p 넘게 개선**될 때만 채택합니다. 영어 구절 유지와 핵심 의미도 직접 대조합니다.
4. 입력·출력 라우팅, 일시정지, 재연결, 확정 자막·전사 저장과 한영 UI를 검증합니다. 현재의 고정 이름 교정을 중복 적용하지 않습니다.

`app/model_resolver.py`는 파일 전체를 지운 것이 아니라 수동 연결 검사만 남겼습니다. 위 목록 외에도 의존성 문서에 적힌 여러 파일에서 관련 코드가 제거되었습니다.

| 다른 제거 기능 | 이유 |
|---|---|
| 음악/발화 분류와 챕터 | 실제 찬양을 발화로 판정했고, 이진 음향 분류로 예배 순서를 신뢰성 있게 추론하지 못했습니다. |
| 자동 언어 리셋 | 한국어가 수동 조작 없이 돌아온 기록이 있어, 세션 리셋 대신 잘못된 출력의 숨김·음소거를 선택했습니다. |
| 모델 카탈로그와 폴백 | 운영자가 지정한 번역 모델을 일관되게 사용하고, 지원되지 않는 모델로 조용히 바뀌는 경로를 없앴습니다. |
