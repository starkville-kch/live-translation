# 기술 결정 및 아키텍처 원칙 (Technical Decisions & Rationale)
### 실시간 예배 번역 시스템 / Live Translation System

이 문서는 시스템의 주요 기술적 결정, 대안 비교, 실패 경험 및 불변 원칙(Invariants)을 영구 보존하기 위한 기술 아키텍처 문서입니다.

---

## 1. 전사 설정 단순화와 검증 근거

한국어 설교에는 영어 문장이 섞이므로 입력을 한국어로 강제하지 않습니다. 입력 및 출력 전사는 모두 빈 `AudioTranscriptionConfig()`로 켜고, `language_codes`, `custom_vocabulary`, 시스템 지시문을 보내지 않습니다. `echo_target_language=True`는 출력 언어로 말한 발화를 유지하기 위한 설정입니다.

SDK가 특정 필드를 전송할 수 있다는 사실만으로 모델의 정확도 개선을 보장할 수 없습니다. 짧은 동일 클립 비교에서는 기존 힌트를 제거했을 때 영어 표현 유지에 뚜렷한 차이가 없었습니다. 11월 8일 기존 라이브 전사를 새로 제공된 Gemini·ChatGPT 기계 전사본과 비교한 발화 CER는 각각 **18.0%, 19.1%**, Gemini 기준 설교 구간은 **18.0%**입니다. 두 기계 전사본끼리도 비교 방향에 따라 **9.5%, 12.6%** 차이가 납니다. 이는 기준 자료의 불확실성을 보여주며 사람이 확정한 정답 대비 정확도나 새 버전의 개선치가 아닙니다.

따라서 효과가 입증되지 않은 힌트·검토 흐름을 제거하고, 수동 이름 교정은 확정 자막의 로컬 후처리로 한정합니다. 점수·명령·정렬 한계와 유료 호출 전 검토할 오프라인 전사 제안은 [evaluation.md](evaluation.md)를 참고하세요. 이 작업에서 새 유료 API 전사는 실행하지 않았습니다.

## 2. 수동 일시정지와 세션 경계

`Pause`는 마이크 캡처·레벨 미터·MP3 녹음을 유지하면서 번역 전송을 멈춥니다. 기존 Gemini 연결을 닫고 번역용 오디오 큐를 비우며 타깃별 최신 유효 핸들은 메모리에 보존합니다. `Resume`과 자동 GoAway 교체는 같은 모델의 문맥 재개를 요청합니다. 수동 재개는 세션 세대(epoch)를 증가시켜 이전 연결의 늦은 응답을 폐기합니다. 핸들이 없거나 거부되면 새 문맥으로 한 번 연결하며, 할당량 오류의 기존 제한은 유지합니다. `Stop`은 핸들을 지우므로 다음 `Start`는 새 문맥입니다.

음악, 스테레오 입력, 언어 이탈 사이의 원인은 이번 자료로 확정할 수 없습니다. 사용자는 Fifine M9를 모노로 바꾼 뒤 좋아졌다고 관찰했지만 같은 음성의 통제 비교는 아닙니다. 2026-11-09 사무실 시험에서는 재접속 없는 최초 한국어 발화도 일본어로 전사됐고 영어 의미는 맞았습니다. 언어 오류를 음악·재연결 문제로만 한정하지 않습니다. 수동 재개가 인식 오류를 반드시 바로잡는다고 안내하지 않습니다. 11월 8일 로그에서 언어가 돌아온 시점 주변에 Pause/Resume 이벤트가 없어 해당 복구는 수동 초기화 근거가 없습니다.

이전의 새 문맥 연결은 누적에 따른 품질 저하 우려로 선택한 동작이었습니다. 2026-11-09의 [1차 조사](/docs/song_language_investigation.md)에서 언어 힌트가 이탈을 예방하지 못했고, [짧은 문맥 유지 시험](/docs/reconnect_context_experiments.md)을 거쳐 B1을 구현했습니다. [전체 예배 검증](/docs/b1_full_service_validation.md)에서 76분54초 동안 8회 재개, 긴 번역 블록 재송출 없음과 후반 발화 오류율을 확인했습니다. 송영의 잘못된 언어·영어는 남아 있어 모든 음악 오인식의 해결책은 아닙니다. P는 검증 자료를 보존한 대안이며 실행 중인 자동 대체 기능이 아닙니다.

## 3. 치명적 오류(Fatal)와 일시적 오류(Transient)의 격리

### 결정
오류 유형을 명확히 구분하여 불필요한 재연결 및 서비스 재시작 루프를 차단합니다:

- **일시적 네트워크 오류 (Transient)**: WebSocket 연결 끊김, 타임아웃 등 → 지수 백오프(Exponential Backoff) 재연결 및 자동 복구 루프 수행. `GoAway`는 백오프 없이 0.2초 즉시 재연결합니다 (`/docs/TECHNICAL.md`).
- **치명적 설정/스키마 오류 (Non-retryable)**: `ValueError`, `TypeError` (잘못된 LiveConnectConfig, 지원되지 않는 SDK 필드 등) → **즉시 FAILED 상태로 전이**하고 재시도 및 자동 서비스 재시작을 중단합니다.
- **지출 한도·할당량·요청 빈도 제한**: HTTP 429, `RESOURCE_EXHAUSTED` 또는 결제 제한 오류는 원인을 한영으로 표시하고 제한된 재시도 후 중단합니다. 연결에 잠시 성공해도 같은 제한 오류의 실패 횟수를 지우지 않으며, 바깥 자동 재시작 루프로 다시 들어가지 않습니다. 실제 청구 한도인지 일시적인 요청 제한인지는 오류 코드만으로 확정하지 않습니다.

## 4. 설정 모델 고정

`config.yaml`의 `gemini.model`을 연결과 재연결에 그대로 사용합니다. 시작 시 모델 목록 조회, 선호 모델 선택, LKG 저장, 자동 대체 경로를 제거했습니다. 지정한 모델이 없거나 접근할 수 없으면 모델명을 포함한 오류를 표시하고 중단합니다. 다른 모델로 조용히 바꾸지 않습니다.

운영자 화면에는 고정 모델명과 수동 연결 테스트만 남습니다. 테스트는 설정 모델을 사용하며 선택값을 저장하지 않습니다. 모델 변경은 유지보수자가 설정 파일을 수정한 뒤 프로그램을 다시 시작하는 작업입니다.

## 5. 원문 언어 자동 감지와 다국어 입력

주 용도는 한국어 예배의 영어 통역이며 중국어 등 다른 언어의 사용도 프로그램이 차단하지 않습니다. 운영자는 출력 언어만 선택하고 모델이 입력 언어를 감지합니다. 기존 `translation.expected_source_languages`는 무시하므로 이전 설정을 복사해도 한국어·영어로 제한되지 않습니다.

입력 `language_code`는 전사 라벨과 로그에만 사용합니다. 정보가 없거나 늦게 와도 수신한 자막과 번역 음성을 전달하고 전사를 저장합니다. 언어 코드가 없는 턴은 `unknown`으로 기록하며 문자 모양으로 언어를 추측하지 않습니다. 언어가 바뀌어도 자동 음소거·출력 숨김·세션 리셋을 하지 않습니다.

언어 코드만으로 실제 중국어 발화와 모델의 중국어 오인식을 구별할 수 없습니다. 언어별 차단을 없앤 대신 오인식도 그대로 전달될 수 있으며, 필요하면 운영자가 Pause/Resume으로 새 번역 세션을 엽니다. 이는 전사 정확도나 모든 언어의 모델 지원을 보장하지 않습니다.

## 6. Public HTTPS, Named Cloudflare Tunnel & PublicHostGuard 보안 경계 (Release v3.0.0)

### 1. 포트 8080 영구 표준화
- Windows 환경에서 포트 80은 IIS, Apache, Docker, VMware, 대학 전산망 백그라운드 서비스와의 충돌 가능성이 높습니다.
- 포트 8080을 표준으로 고정(`config.yaml`, `app/config.py`, `app/tunnel.py`, `check_skc_live.bat`, Cloudflare Tunnel ingress)하여 충돌 위험을 원천 제거하고, 로컬 Wi-Fi(`http://skc.local:8080`) 및 공인 HTTPS(`https://live.starkvillekoreanchurch.org`) 양쪽 모두에서 일관된 동작을 보장합니다.

### 2. PublicHostGuardMiddleware 기본 거부 (Default-Deny) 원칙
- 공인 Cloudflare 터널 도메인으로 들어오는 모든 HTTP 요청은 `PublicHostGuardMiddleware`를 통과합니다.
- **공개 허용**: `/live`, `/stream`, `/audio-stream`, `/ws/telemetry`, `/logo*`, `/static/*`.
- **자동 리다이렉트**: 공인 도메인의 루트(`/`) 접속 시 참석자 화면(`/live`)으로 자동 rewrite.
- **원천 차단 (404)**: `/admin`, `/api/devices`, `/api/start`, `/api/stop`, `/api/pause`, `/api/resume`, `/api/qr.png` 등 모든 관리자 및 제어 라우트는 공인 도메인 유입 시 404를 반환하여 외부에서의 공격 표면(Attack Surface)을 0으로 만듭니다.

### 3. 암호학적 운영자 인증 (HMAC-SHA256 Session Cookies)
- 운영자 기능 보호를 위해 `.env`의 `SKC_OPERATOR_PASSWORD` 기반 HMAC-SHA256 서명 세션 쿠키(`HttpOnly`, `SameSite=Strict`)를 구현했습니다.

### 4. 텔레메트리 지연 시간 분해 모델
- 체감 지연 시간을 세 단계로 분해하여 투명하게 모니터링합니다:
  $$\text{공용 체감 지연 (E2E)} = \text{Gemini AI 처리 지연 (Turn-Onset)} + \text{네트워크 RTT} + 200\text{ms (재생 버퍼)}$$
- 운영자 콘솔에서는 세부 RTT 및 지연 수치를 접이식 아코디언에 보관하고, 대시보드에는 핵심 지표(`공용 체감 지연 ~1.1s`)를 3x2 그리드로 컴팩트하게 노출합니다.

### 5. 병렬 멀티스레드 빌드 파이프라인
- `build_parallel.py`를 통해 `SKC_translation.spec`과 `SKC_setup.spec`을 멀티코어 환경에서 병렬 실행하여 바이너리 패키징 시간을 50% 단축하고, 콘솔에 실시간 진행 마일스톤과 실제 경과 시간(Wall-clock time)을 출력합니다.

## 7. 다중 타겟 실시간 통역 및 런타임 안정화 원칙 (Release v3.1.0)

### 1. 단일 오디오 캡처 + 다중 타겟 팬아웃 (One-Audio Multi-Session)
- **결정**: 하드웨어 마이크/믹서는 오직 1개의 `AudioCapture` 인스턴스만 독점 점유합니다.
- `TranslationManager`가 캡처된 단일 16kHz PCM 청크를 메모리 내에서 활성화된 각 타겟 세션(`GeminiSession[lang]`)으로 비동기 팬아웃합니다.
- **불변 원칙**: 타겟 언어가 3개 이상 추가되더라도 마이크 장치 캡처 스레드는 항상 1개만 동작해야 하며, 오디오 장치를 중복 오픈하거나 별도 프로세스를 띄우지 않습니다.

### 2. 방향성 세션 장애 격리 (Directional Failure Isolation)
- **주 타겟(Primary: EN) 장애 시**: 보조 타겟(Secondary: ZH, ES) 세션과 마이크 캡처는 중단 없이 지속됩니다. 운영자 화면의 `[발화]` 미리보기만 주 세션 재연결 동안 일시 멈췄다가 복구 시 중복/깨짐 없이 재개됩니다.
- **보조 타겟(Secondary) 장애 시**: 주 타겟(EN) 통역, 운영자 화면, 마이크 캡처는 어떠한 지연이나 중단도 겪지 않습니다.
- **불변 원칙**: 특정 언어 세션의 일시적 끊김이나 오류가 다른 언어 청취자나 전체 번역 파이프라인을 중단시키지 않아야 합니다.

### 3. 참석자 Web Audio 동기식 제스처 활성화 (User-Gesture Activation)
- 모바일 브라우저(iOS Safari / Android Chrome)는 비동기 콜백 중간에 생성되거나 재개되는 `AudioContext`를 `suspended` 상태로 차단합니다.
- **결정**: 이어폰 확인 모달의 `[확인]` 버튼 클릭 이벤트 핸들러 스택 내부에서 즉시 동기식으로 `AudioContext.resume()`을 호출한 뒤 비동기 WebSocket 연결 및 UI 업데이트를 진행합니다.
- 다중 언어 3개 탭 동시 청취는 단일 PC 사운드카드 공유 시 경합이 발생할 수 있으나, 실제 운영 환경에서는 개별 참석자의 독립 기기에서 1인 1컨텍스트로 완전히 격리되어 재생됩니다.

### 4. 자발적 셧다운 수명주기 (Voluntary Shutdown Lifecycle)
- 기존에는 Ctrl+C 발생 시 Uvicorn이 3초 graceful timeout 동안 SSE 큐 대기(`queue.get()`)를 강제 종료하면서 ASGI `CancelledError` 및 `KeyboardInterrupt` 트레이스백을 출력했습니다.
- **결정**:
  1. 전역 `shutdown_event = asyncio.Event()` 및 `signal_shutdown()` 도입.
  2. `SKCUvicornServer` 서브클래스에서 OS 첫 번째 시그널 포착 즉시 `signal_shutdown()` 트리거.
  3. `_sse_generator`, `audio_stream`, `telemetry_stream`이 0.5초 타임아웃으로 이벤트를 확인하고 **자발적으로 리턴**하여 스트림을 우아하게 종료.
  4. `main.py` 프로세스 경계에서 `KeyboardInterrupt`를 정상 종료로 처리.

### 5. 오프라인 고정 린팅 원칙 (Pinned Offline Static Linting)
- 테스트 스위트 내에서 `npx -y`를 호출하면 네트워크 동적 다운로드 의존성 및 미래 버전 파편화가 발생합니다.
- **결정**: `package.json`에 `eslint: 10.9.1`을 로컬 개발 의존성으로 고정하고, 테스트 스위트에서는 `npx --no-install eslint`를 호출하여 100% 오프라인 상태에서도 `no-undef` 정적 검증이 보장되도록 합니다.

### 6. 서버 렌더링 템플릿 및 패키징 (Jinja2)
- 운영자 인증 모달과 동적 레이아웃은 클라이언트 측 JS 실행 전 서버 사이드 Jinja2 템플릿(`app/templates/operator/_auth_modal.html`)으로 완성되어 전송됩니다.
- 단일 실행 파일 빌드 시 `jinja2`가 번들에 누락되지 않도록 `requirements.txt`와 `SKC_translation.spec`에 명시적 의존성으로 등록 및 관리합니다.

## 8. 로컬 교정, 주석 보존 설정 및 네트워크 분리

### 확정 자막의 이름 교정
`config/name_corrections.yaml`은 유지보수자가 직접 관리하는 정확 일치 치환표입니다. 긴 항목을 먼저 적용하고 영어 항목은 단어 경계를 검사합니다. 확정 원문·번역 자막과 전사 파일에만 적용하며, Google에 보내거나 합성 음성을 바꾸지 않습니다. 단어나 짧은 구절이 5회 이상 연속 반복되면 한 번으로 축약합니다.

### 주석 보존 YAML 설정
설정 저장은 `_update_yaml_scalar`, `_update_yaml_list`의 인플레이스 치환을 사용해 기존 주석과 줄 구조를 보존합니다. Windows의 일시적 파일 잠금에는 제한된 재시도를 사용합니다.

### 네트워크 설정 분리와 적응형 로컬 모드
`intranet`은 현장 Wi-Fi, `internet`은 공용 Cloudflare 접속을 담당합니다. 터널 토큰이 없거나 `enable_tunnel: false`이면 현장 Wi-Fi 전용 화면으로 동작합니다. 기존 운영자 인증과 공인 호스트의 제어 API 차단은 유지합니다.

새 설치용 기본값과 템플릿은 공용 접속을 끄고 공용 URL을 비워 둡니다. 기존 설정은 유지합니다. 설정 마법사의 `3. PUBLIC HTTPS (Advanced)`는 항상 접힌 상태로 시작하며, 공용 URL과 토큰 또는 확인된 터널 서비스가 없으면 선택적 준비상태 배지를 숨깁니다. 고급 영역은 바로 펼치고 서비스 조회는 백그라운드에서 한 번씩 수행합니다. 작업 스레드는 결과 큐만 채우며 Tk 이벤트 루프가 서비스 상태·바이너리 상태·준비상태 배지를 갱신합니다. 작은 창에서는 내용을 스크롤하며 저장 버튼은 고정합니다. 입력한 API 키와 연결 시험 통과는 별도 상태로 표시합니다. 고정 공용 접속을 사용하려면 본인의 계정·도메인·터널을 준비합니다. [Cloudflare 준비 조건](https://developers.cloudflare.com/tunnel/get-started/).

운영자 비밀번호는 현장 운영자 화면의 선택적 인증이며 공용 터널 전용 설정이 아닙니다. 공용 HTTPS의 운영자 경로 차단과 별개로 적용됩니다. 비워 두면 현장 운영자 화면의 인증을 생략합니다.

설정 저장 후 `qr_local.png`와 자체 포함 인쇄 페이지 `qr_local_print.html`을 실행 파일 옆에 만듭니다. QR은 참석자 접속 URL만 포함하며 Wi-Fi 자동 연결이나 자격 증명 공유 기능이 아닙니다. 생성 실패는 이미 저장한 설정과 구분해 알립니다. 휴대폰은 같은 현장 네트워크에 연결하고 프로그램이 실행 중이어야 하며, PC는 Gemini용 인터넷이 필요합니다.

배포 ZIP에는 두 EXE, 한국어·영어 설치·사용 PDF와 버전이 표시된 HTML 안내를 포함합니다. 예배 때는 `SKC_translation.exe`, 처음 설정할 때는 `SKC_setup.exe`를 실행합니다. 개발용 `SKC_start.bat`은 배포하지 않으며 남아 있는 사본도 ZIP에서 제외합니다. 필수 EXE 또는 어느 언어의 PDF든 없으면 패키징을 중단합니다. 안내서 예시는 Jackson Korean Church(JKC)로 통일하고 장비 브랜드·교회별 수신기 설정은 배포 안내에 넣지 않습니다. 루트 README·CHANGELOG는 GitHub 링크로 안내하고 ZIP에서 제외하며 시작 시 다시 추출하지 않습니다. 저장소와 EXE 내부의 영문 `CHANGELOG.md`는 유지합니다. `licenses/`의 고지는 유지합니다. `cloudflared.exe`는 공용 HTTPS를 사용할 때 설정 마법사에서 다운로드하며, 빌드 폴더에 남은 바이너리도 ZIP에서 제외합니다.

## 9. 원시 입력 MP3 백업과 시간축

- 마이크를 실제로 연 샘플레이트·채널 수의 PCM16을 모노 변환과 번역용 16 kHz 리샘플링 **전에** 녹음기로 보냅니다. 녹음을 위해 하드웨어 캡처 설정을 바꾸지는 않습니다. 장치가 네이티브 16 kHz 모노로 열렸다면 MP3도 그 포맷을 사용합니다.
- 내장 `lameenc`로 약 128 kbps CBR MP3를 기록하며 용량은 시간당 약 58 MB입니다. bounded 큐와 별도 writer로 디스크 지연이나 인코더 실패를 번역 경로와 격리합니다. 일시정지 중에도 녹음하며 누락 구간은 무음과 메타데이터로 남깁니다.
- `logs/recordings/current_week/YYYY-MM-DD_HHMM.mp3`로 저장합니다. 예배 후 3주까지 사후 전사를 요청할 수 있도록 새 녹음 시작 시 21일보다 오래된 생성 파일을 정리합니다. 고정 코드 값이며 새 설정은 없습니다. 달력상 ISO 주 기준이 아닙니다. 잠긴 파일은 경고를 남기고 현재 녹음을 이어갑니다. 보관할 파일은 별도로 복사해야 합니다.
- `started_at`은 시간대가 있는 녹음 시작 시각입니다. 영상과의 시작 시차를 먼저 맞추고, 전사 `offset_seconds`가 발화 시점이 아닌 번역 도착 시점임을 고려해 추가 지연을 보정합니다. `elapsed_seconds`는 일시정지를 포함하고 `runtime_seconds`는 실제 번역 가동 시간입니다.
- 우선순위는 실시간 통역입니다. 녹음은 YouTube 업로드 영상의 오디오 누락에 대비한 보조 수단으로, 필요하면 MP3를 영상에 더빙·정렬합니다. 사후 전사는 그때 요청하는 별도 작업이며 평상시 자동 처리로 추가하지 않습니다. 설교 구간의 개선 가능성과 재사용할 평가 자료는 [보류 계획](/docs/PLAN.md)과 [평가 기록](/docs/evaluation.md)에 보존합니다.
- 입력 채널별 RMS dBFS와 스테레오 L/R 상관관계는 시작 및 60초마다 로그에 남깁니다. 자동 입력 모드 변경이나 새 화면 조작은 없습니다.

## 10. 비용과 운영 범위

2026-11-08 확인한 Live Translate 공개 합산 요율은 대상 언어당 분당 약 US$0.037입니다. 70분·한 언어의 주일 예배는 약 US$2.50~2.60, 월 약 US$11 수준입니다. 실제 비용은 입력·출력 음성 토큰으로 청구됩니다. 최근 주일의 `summary.txt` 추정이 결제 화면과 맞았다는 것은 사용자가 확인한 운영 기록입니다. [공식 요금표](https://ai.google.dev/gemini-api/docs/pricing/).

- 출력 언어마다 별도 유료 세션입니다. 참석자 수는 세션 수를 늘리지 않습니다. 2026-09-19의 34분·5개 언어 시험 비용은 US$6.21이었습니다(사용자 제공 기록).
- 현재 Live Translate는 음성과 전사 텍스트를 함께 반환합니다. 자막만 요청해 음성 출력 비용을 없애는 모드는 채택할 수 없습니다(2026-11 공식 모델 설명 확인). [지원 출력](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-live-translate-preview), [연결 설정](https://ai.google.dev/gemini-api/docs/live-api/live-translate).
- 찬양 중 일시정지로 약 20%를 줄이는 방안은 채택하지 않습니다. 같은 PC에서 PowerPoint와 브라우저를 계속 전환해야 하므로 봉사자가 지속해서 운영하기 어렵습니다.
- 실시간 전사와 텍스트 번역을 조합한 자막 전용 방식은 분당 약 US$0.01의 초기 추정이 있으나, 영어 음성이 사라지고 상당한 재구현이 필요하므로 보류합니다. 청취자가 음성 통역을 사용하지 않는다고 확인될 때만 재검토합니다. 이 금액은 실제 측정이 아닙니다.
- 평소에는 출력 한 언어를 사용하고, 인사에서 시작해 축도 후 종료합니다. 여러 언어의 시험은 1~2분으로 제한합니다.
- 예배 후 전사는 자동 실행하지 않습니다. 승인된 1회 평가 결과는 [평가 문서](/docs/evaluation.md)에 기록합니다. 향후 별도 요청형 도구도 제안 승인 전에는 만들지 않습니다. 교회 음원은 유료 프로젝트 키로만 보냅니다.

## 11. 평상시 시작 시간 기록

`SKC_translation.exe`의 평상시 실행마다 `logs/startup.log`에 일시·단계별 소요 시간·한 줄 요약을 남깁니다. 직접 실행에서는 Python 진입 후의 계측이며, 개발용 배치가 제공하는 진입 전 시각은 포함하지 않습니다. 시작 완료 후에는 작업별 첫 측정만 남기고 같은 상태 조회의 반복 측정은 기록하지 않습니다. 시작 중의 모든 측정과 시작 전후에 걸친 작업의 완료 기록은 유지합니다. 로그는 고정 크기로 순환하며 설정과 UI를 추가하지 않습니다. 브라우저 실행 요청 시각은 측정하지만 실제 페이지가 화면에 그려진 시각으로 해석하지 않습니다. 교회 PC의 다음 주일 실행 기록으로 원인을 판단하며 별도 진단 방문은 필요하지 않습니다. 파일 구성과 검증은 [빌드 문서](/docs/BUILD_EXE.md)에 있습니다.
