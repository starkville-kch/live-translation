# 예배 전사록 비교와 채점

`/tools/eval/score_transcript.py`는 실시간 통역에서 저장한 원문 전사록을 두 기계 전사본과 비교하는 개발용 도구입니다. 음원을 업로드하거나 API를 호출하지 않습니다. Python과 NumPy가 필요하며, 운영용 EXE에 포함하지 않습니다.

## 입력 자료

2026-11-09의 찬양 중 언어 이탈 [1차 조사](/docs/song_language_investigation.md)는 9~11월 저장 로그·재연결 관계와 같은 310초 음원의 현재 설정·언어 힌트 비교를 다룹니다. [문맥 유지 후속 시험](/docs/reconnect_context_experiments.md)은 프라이밍과 세션 재개를 각각 3회 비교한 결과와 구현 권고입니다. 아래의 전체 전사 CER 및 사후 전사 평가와는 별개이며 제품에는 아직 적용하지 않았습니다.

`/tools/eval/data/2026-11-08/`에 다음 자료를 보관합니다. 제공된 원본은 `.agent/sessions/20261108_121729/`에도 그대로 남겨 두었습니다.

| 파일 | 내용 |
|---|---|
| `transcript.md` | 11월 8일 예배의 기존 실시간 통역 내보내기, 91개 블록 |
| `2026_11_8_recording_full_transcript.md` | Gemini 전사본, 제목별 구간 형식. 제공된 `_gemini.md` 파일을 이 이름으로 복사 |
| `2026_11_8_recording_full_transcript_chatgpt.md` | ChatGPT 전사본, 녹음 시각이 있는 5분 단위 구간 형식 |
| `facts.json` | 교회명, 창립 연수, 인명 등 사실 확인용 정규식. 제공된 `facts_2026-11-08.json`의 복사본 |

두 기준 전사본 모두 사람이 검수한 정답이 아닙니다. Gemini 전사본의 구간 시각은 실제 녹음과 맞지 않는 부분이 있습니다. 채점기는 시각을 사용하지 않고, 각 기준 구간과 가장 잘 맞는 실시간 원문 부분을 찾아 비교합니다.

## 실행

저장소 루트에서 각 명령을 한 번씩 실행합니다. 두 기준에 대한 결과를 항상 함께 보고합니다.

```powershell
conda run --no-capture-output -n agent python tools/eval/score_transcript.py tools/eval/data/2026-11-08/2026_11_8_recording_full_transcript.md tools/eval/data/2026-11-08/transcript.md --facts tools/eval/data/2026-11-08/facts.json
```

```powershell
conda run --no-capture-output -n agent python tools/eval/score_transcript.py tools/eval/data/2026-11-08/2026_11_8_recording_full_transcript_chatgpt.md tools/eval/data/2026-11-08/transcript.md --facts tools/eval/data/2026-11-08/facts.json
```

`--json <경로>`를 추가하면 같은 결과를 JSON으로 저장합니다. 새 실시간 내보내기나 사후 전사본을 평가할 때는 두 번째 인자의 파일 경로만 바꿉니다. 비교할 파일은 기존 `## HH:MM:SS`, `**Spoken ...**`, `**English**` 블록 형식을 유지해야 합니다. 단순 원문 파일이면 이 형식으로 먼저 변환해야 하며, 평가를 위해 없는 영문 번역을 만들어 넣으면 안 됩니다.

## 2026년 11월 8일 기준 결과

제공된 채점기를 수정하지 않고 기존 실시간 내보내기에 실행한 결과입니다.

| 비교 기준 | 말소리 구간 CER | 기준 문자 수 |
|---|---:|---:|
| Gemini 전사본 | 18.0% (3,027 / 16,780) | 16,780 |
| ChatGPT 전사본 | 19.1% (3,246 / 17,029) | 17,029 |

Gemini 기준의 주요 구간은 다음과 같습니다.

| 구간 | CER |
|---|---:|
| 환영 인사 | 50.9% |
| 시편 99편 교독 | 6.8% |
| 개회 기도 | 10.2% |
| 사도신경 | 9.6% |
| 회중 대표 기도 | 3.7% |
| 교회 소식 및 성경 봉독 | 41.5% |
| 설교 | 18.0% |
| 설교 후 기도 | 9.3% |

찬양 구간 CER는 Gemini 기준으로 약 39~85%였습니다. 제목에 `찬양`, `찬송`, `연습`, `특송`이 들어간 구간은 말소리 합계에서 제외합니다. 따라서 봉헌 기도가 특송과 같은 구간에 있으면 그 기도도 합계에서 빠집니다. ChatGPT 형식에서는 `찬양`으로 표시한 항목을 제외하고, 사용할 말소리가 거의 없는 구간도 제외합니다.

두 기준끼리 비교하면 Gemini 구간을 기준으로 ChatGPT 말소리를 채점한 값은 9.5% (1,602 / 16,780)입니다. 반대 방향은 12.6% (2,142 / 17,029)입니다. 구간 분할과 비교 방향이 다르므로 같은 값이 나오지 않습니다. 이를 대칭적인 오차율이나 사람의 검수 정확도로 해석하면 안 됩니다.

## 결과 해석

- CER는 띄어쓰기와 문장부호를 제거한 문자 편집 거리입니다. 영어를 한글 발음으로 적은 경우도 오류로 셉니다.
- 앞뒤를 자유롭게 맞추는 구간 정렬이므로, 전체 음원에서 빠진 말소리나 중복을 모두 검출하는 지표가 아닙니다. 짧은 구간은 비슷한 다른 발화에 맞춰질 수 있습니다.
- 영문 출력은 대응하는 정답 번역이 없으므로 번역 품질 점수를 계산하지 않습니다. 영어 구절 검사는 해당 단어가 다른 곳에라도 등장하는지 확인하는 참고 지표입니다.
- `facts.json` 검사는 정규식 일치 여부만 확인합니다. 같은 사실의 맞는 표현과 틀린 표현이 함께 발견될 수 있고, 문장의 주체나 도움 요청의 방향까지 판단하지는 못합니다.
- 두 기준이 서로 다르고 모델 실행에도 변동이 있으므로, 1~2%p 차이만으로 개선을 확정하지 않습니다. 양쪽 CER, 잘못된 고유명사, 핵심 의미 오류를 함께 확인합니다.

기준 결과의 JSON은 다음 파일에 저장되어 있습니다.

- `/tools/eval/data/2026-11-08/baseline-gemini.json`
- `/tools/eval/data/2026-11-08/baseline-chatgpt.json`
- `/tools/eval/data/2026-11-08/reference-agreement.json`

## 추가 승인 후 실행한 오프라인 전사 평가

전체 결과는 **기존 라이브 전사를 명확히 앞서지 못했습니다.** 설교와 일부 이름·사실은 개선됐지만, 예배 중 여러 발화 구간이 빠졌고 양쪽 기준의 전체 말소리 CER가 모두 나빠졌습니다. 따라서 별도의 `SKC_backup_transcript.bat` 제작을 제안하거나 구현하지 않았습니다. 추가 유료 요청도 실행하지 않았습니다.

### 실행 조건과 원본 보존

사용자는 Addendum 2의 약 US$0.50 평가 한 건을 승인한 뒤, `.env`의 `GEMINI_API_KEY`가 유료 프로젝트 키라고 명시적으로 확인했습니다. 그 확인 후에만 음원을 업로드했습니다. 키 값은 출력하거나 결과 파일에 저장하지 않았습니다.

- 모델: `gemini-3.5-transcribe`, Interactions API, `store: false`.
- 음원: 제공된 `2026_11_8_recording.mp3`, 5,415.020초, 48 kHz 스테레오.
- 분할: 00:00~45:00과 45:00~끝의 두 요청. 원본을 PCM16 FLAC으로 무손실 디코딩해 샘플레이트·채널을 유지했으며 리샘플링, 모노 변환, 새 MP3 압축은 하지 않았습니다.
- 입력 힌트: `language_codes: [ko, en]`, `mode: {type: verbatim}`.
- 어휘: [복구한 용어 파일](archive/glossary_terms.yaml)의 모든 한국어·영어 표제어와 변형에 `스타크빌 한인교회`, `카미카`, `옥한흠`, `John Stott`, `Charles Spurgeon`을 더한 **174개 고유 항목**. 기존 `enabled: false` 항목도 이번 요청에는 포함했습니다. 실제 목록은 [manifest.json](../tools/eval/data/2026-11-08/offline-transcribe/manifest.json)에 있습니다.
- 화자 구분·단어별 시각·영문 번역은 요청하지 않았습니다. 이름 로컬 교정도 결과에 적용하지 않았습니다.
- 추론 요청은 정확히 두 번이며 자동 재시도를 껐습니다. 각 요청 전 배타적 실행 표식을 저장해 같은 폴더에서 실수로 재실행되지 않도록 했습니다. 응답 원문과 사용량을 먼저 저장하고, 업로드 파일은 각 요청 후 삭제했습니다.

공식 모델의 입력 한도는 요청당 1시간입니다. 어휘 목록은 최대 1,000개를 지원하지만 보통 100개 이하에서 좋은 결과를 낸다고 안내하며, 사용자 어휘와 화자 구분·단어별 시각은 함께 쓸 수 없습니다. 이번 174개 목록의 효과를 별도로 분리한 대조 실험은 하지 않았습니다. [공식 모델 설명](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe), [공식 전사 설정](https://ai.google.dev/gemini-api/docs/transcribe).

두 FLAC을 이어 디코딩한 PCM16은 원본 MP3를 디코딩한 PCM16과 **1,039,683,840바이트 모두 동일**했습니다. SHA-256은 `1c7dae5c0a1738a8744510d3e7f57eeb52ec27549765215b2ac1aba66ad3618b`입니다. 따라서 아래 누락을 음원 분할 과정에서 오디오를 잃은 결과로 설명할 수는 없습니다. [무결성 결과](../tools/eval/data/2026-11-08/offline-transcribe/audio_integrity.json).

### CER와 누락 징후

제공된 채점기를 그대로 사용했습니다. 아래는 원문 인식 비교이며 실시간 영문 통역 품질 비교가 아닙니다.

| 비교 기준 | 기존 라이브 | 새 오프라인 전사 | 변화 |
|---|---:|---:|---:|
| Gemini, 말소리 합계 | 18.0% (3,027 / 16,780) | 22.6% (3,788 / 16,780) | 4.5%p 악화 |
| ChatGPT, 말소리 합계 | 19.1% (3,246 / 17,029) | 19.9% (3,381 / 17,029) | 0.8%p 악화 |
| Gemini, 설교 구간 | 18.0% | 12.1% | 5.9%p 개선 |

Gemini 기준의 주요 구간을 비교하면 다음과 같습니다. 기준 전사본의 잘못된 시각을 그대로 실제 녹음 위치로 해석하면 안 됩니다.

| 구간 | 기존 라이브 CER | 오프라인 CER |
|---|---:|---:|
| 환영 인사 | 50.9% | 6.4% |
| 시편 99편 교독 | 6.8% | 0.0% |
| 개회 기도 | 10.2% | 0.5% |
| 사도신경 | 9.6% | 85.7% |
| 참회의 기도·사죄의 확신 | 36.8% | 85.2% |
| 회중 대표 기도 | 3.7% | 87.8% |
| 교회 소식·성경 봉독 | 41.5% | 44.1% |
| 설교 후 기도 | 9.3% | 2.7% |
| 축도·폐회 | 40.4% | 7.7% |

사도신경·참회·대표 기도에 해당하는 내용은 새 결과에서 대부분 찾을 수 없습니다. 이 세 기준 구간은 2,262자로 Gemini 말소리 기준의 13.5%에 해당합니다. ChatGPT 기준에서도 녹음 25·30·35분 구간의 CER가 각각 85.8%, 88.0%, 85.8%로 높습니다. 이 세 구간은 2,454자로 해당 말소리 기준의 14.4%입니다. 이는 기준 전사본 대비 광범위한 누락 징후를 보여주지만, 전체 실제 발화의 누락률을 측정한 값은 아닙니다.

두 API 응답 모두 `status: completed`였고 `model_output` 단계가 하나씩 있었습니다. 첫 구간은 2,251자·1,214출력 토큰, 둘째는 17,589자·8,591출력 토큰입니다. 원시 응답에는 `finish_reason`, 출력 한도, 명시적인 잘림 표식이 없었으며 요청에도 별도 출력 토큰 제한을 넣지 않았습니다. 공급자가 완료로 보고했다는 사실만으로 모든 발화를 전사했다고 판단할 수 없습니다. 누락의 원인이 모델 내부 길이 처리인지, 음향·채널 처리인지 등은 이번 두 요청으로 확정하지 못했습니다.

### 고유명사와 의미 확인

`facts.json`의 한국어 정규식 일치는 기존 3개에서 새 결과 10개로 늘었습니다. 영문 번역은 생성하지 않았으므로 채점 결과의 영어 `MISSING`은 적용 대상이 없는 열입니다. 아래 표는 정규식 결과와 주변 문장 확인을 함께 요약한 것입니다.

| 확인 항목 | 기존 라이브 원문 | 새 오프라인 전사 |
|---|---|---|
| 교회명 | `스타필드`, `스타트 하니` | 도입에서 `스타크빌 한인교회` 정확. 뒤에는 `스탁빌` 표기도 남음 |
| 창립 연수 | `44년` | `44년` 유지 |
| 카미카 | `카미카제` | `카미카` |
| MSU 졸업생 | 일치 없음 | `MSU 졸업생` |
| 도움 요청 방향 | 이전 영문 통역에서 주체가 뒤바뀐 사례 확인 | `우리에게 도움을 요청해 온 MSU 졸업생 카미카 자매를 돕기 위해서`로 기준의 방향 유지 |
| 아버님 소천 | `수술` | `아버님께서 지난 금요일 소천하셨습니다` |
| 에베소서 4장 | 일치 | 일치 유지 |
| 옥한흠 | 일치 없음 | 힌트에 넣었으나 `오카흠`으로 오인식 |
| 중고등부·청년부 | `부처님` 오기 | `중고등부`, `청년부` |
| 녹스빌 | 한국어 일치 없음 | 일치 없음 |
| 파선 | 일치 | 일치 유지 |
| John Stott·Spurgeon | 원문 일치 없음 | `존 스토트`, `스펄전` |

교회명과 카미카가 나아진 사실은 유용하지만, 한 곳에서 올바른 표기가 나왔다고 전체 이름 정확도나 어휘 힌트의 인과 효과를 입증한 것은 아닙니다. 이전 비교에서 확인한 도움 요청 방향 오류는 영문 번역 오류였으며, 이번 원문 전사만으로 영문 통역이 개선됐다고 말할 수 없습니다.

영어 혼용도 여전히 불안정했습니다. `Keep the unity in a visible manner.`는 유지됐지만 `Unity is harmony in diversity.`는 찾을 수 없었습니다. `unity`, `uniformity`, `oneness`, `sameness`는 `유니티`, `유니포미티`, `원네스`, `세임네스`로 남았습니다. 위치와 무관하게 라틴 문자 단어의 존재를 세는 참고 지표는 Gemini 기준 **75/162 → 19/162**, ChatGPT 기준 **37/88 → 14/88**로 낮아졌습니다. 이 지표를 영어 문장 정확도로 해석해서는 안 되지만, 이번 실행이 영어 철자 보존까지 전반적으로 해결했다는 근거는 없습니다.

### 사용량과 비용

### 재현 자료와 다음 판단

정리된 전사·채점·어휘 설정·무결성·비용 자료 9개를 [평가 결과 폴더](../tools/eval/data/2026-11-08/offline-transcribe/)에 유지합니다. 원시 요청·응답·HTTP 정보·실행 표식·분할 텍스트 10개와 추가 분석 자료는 로컬 `.agent/archive/2026-11-08-worship-review/offline_transcribe_20261108/`로 옮겼습니다. Git에는 정리된 평가 자료만 남기며, 원시 유료 응답은 로컬 아카이브에서 다시 확인할 수 있습니다.

제공된 MP3와 기준 전사본은 수정하지 않았습니다. 재생성 가능한 두 FLAC 분할본과 동일한 결과의 중복 사본은 정리했습니다. 원본 MP3, 분할 위치·설정·해시, 전사와 유료 응답은 보존하므로 API를 다시 호출하지 않고도 기존 결과를 검토·채점할 수 있습니다. 로컬 보관 위치는 `.agent/archive/INDEX.md`에 정리했습니다.

[transcribe_evaluation.py](../tools/eval/transcribe_evaluation.py)는 이번 명시적 평가를 재현하기 위한 개발용 스크립트입니다. `prepare`는 로컬 분할·해시·설정 검증만 수행합니다. `run`은 유료 키의 별도 확인이 필요하고 API를 호출하므로 새 실행에는 다시 비용 승인이 필요합니다. 예배 후 자동 실행, 녹음 파일 선택 도구, 배치 파일, 운영자 화면 버튼은 만들지 않았습니다.

추가 API 호출 없이 다음 명령으로 저장 결과를 다시 채점할 수 있습니다.

```powershell
conda run --no-capture-output -n agent python tools/eval/score_transcript.py tools/eval/data/2026-11-08/2026_11_8_recording_full_transcript.md tools/eval/data/2026-11-08/offline-transcribe/transcript.md --facts tools/eval/data/2026-11-08/facts.json
```

```powershell
conda run --no-capture-output -n agent python tools/eval/score_transcript.py tools/eval/data/2026-11-08/2026_11_8_recording_full_transcript_chatgpt.md tools/eval/data/2026-11-08/offline-transcribe/transcript.md --facts tools/eval/data/2026-11-08/facts.json
```

전사 Markdown의 `00:00:00`, `00:45:00`은 **파일 구간 시작 위치**이며 문장·단어의 발화 시각이 아닙니다. 이 결과만으로 영상에 바로 동기화할 수 없습니다. 새 오프라인 전사가 실제 기준 발화를 얼마나 빠뜨렸는지 사람이 해당 녹음을 확인한 뒤 판단해야 합니다. 전체 발화 결과로는 자동화 도구를 채택하지 않되, 설교 구간 개선은 후속 검토의 출발점으로 남깁니다.

사용 목적은 실시간 통역 대체가 아니라 YouTube 오디오 누락 때의 보조 복구입니다. 먼저 보관 MP3로 영상의 소리를 더빙·정렬하고, 전사가 필요할 때만 해당 설교나 누락 구간을 별도로 검토합니다. 이때 현재 스크립트·어휘·기준본·원시 결과를 재사용합니다. 새 도구와 자동 처리는 구현하지 않았으며 추가 유료 실행에는 다시 비용 승인이 필요합니다. [보류 계획](/docs/PLAN.md).
