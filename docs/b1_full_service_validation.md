## 후속 사무실 확인: 최초 연결의 원문 오류

2026-11-09 사용자는 조용한 사무실에서 시작 직후 `아아 하나님은 당신을 사랑하시며 당신을 위한 놀라운 계획을 가지고 계십니다.`라고 한국어로 말했다고 확인했습니다. `20261109_141210` 세션은 약 20초, 재접속 0회였지만 공급자의 입력 전사는 `あ、あ。神様はあなたを愛しており、あなたのために素晴らしい計画を持っておられます。`, 언어 코드는 `ja`였습니다. 영어는 사용자가 말한 의미와 맞았습니다. 앱이 한국어 원문을 일본어로 바꿔 표시한 것은 아닙니다.

이는 긴 찬양·재연결 외에도 최초 연결의 짧은 일반 발화에서 원문 오류가 생길 수 있다는 사례입니다. B1의 재개 검증은 이 오류를 해결했다는 근거가 아닙니다. 이어진 14:17 시험에서는 `하나, 둘, 셋`과 같은 문장의 한국어가 반환됐지만, 시작 조건을 통제한 비교가 아니므로 준비 발화의 예방 효과를 확정하지 않습니다. 정확한 공급자 내부 원인은 확인하지 못했습니다.

이 두 시험은 소스 실행 환경의 `lameenc` 누락으로 입력 MP3를 저장하지 못했습니다. 최초 음성의 파형을 검증하거나 같은 입력으로 재현한 시험은 없으며, 이후 사용자가 설치를 마쳤다고 알렸습니다. 녹음 확인 후 같은 음원의 통제 비교가 필요합니다. 이 후속 조사에서 유료 API를 호출하거나 필터·힌트·프라이밍을 제품에 추가하지 않았습니다.

## 유지할 대안과 보류 항목

- P 프라이밍도 앞선 같은 찬양 시험에서 3회 모두 이탈을 예방했습니다. B1을 다시 검토해야 할 때의 대안으로 스크립트·음원·결과를 보존합니다. 현재 실행 중인 자동 대체 기능은 아니며, 전체 예배 검증이나 자동 프라이머 선택은 수행하지 않았습니다. [앞선 비교](/docs/reconnect_context_experiments.md).
- 음악 분류기와 자동 일시정지는 보류합니다. 송영 오류는 남았지만 이번 작업에서 분류기나 상태 배지를 복구하지 않았습니다. 향후 평가한다면 실제 입력 오디오만 사용하고 슬라이드·장비 형식에 의존하지 않습니다.
- 분류기의 CPU·메모리·로딩 시간은 아직 측정하지 않았습니다. ONNX Runtime을 평가한다면 별도 작업 스레드, `intra_op_num_threads=1`, 순차 실행(`ORT_SEQUENTIAL`), 스피닝 비활성화를 적용합니다. 병렬 실행을 선택할 때만 의미가 있는 inter-op 풀도 제한합니다. 늦은 분류 창은 건너뛰며 캡처·녹음이 기다리지 않게 해야 합니다. [ONNX Runtime 스레드 설정](https://onnxruntime.ai/docs/performance/tune-performance/threading.html).
